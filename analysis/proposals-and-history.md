# Operational proposals and historical work

## Nine unregistered agent upgrades

These are proposals/reference code in upgrades.txt, not installed tools or validated operating capabilities. They are preserved as specifications mapped to existing canonical services.

| Proposal | Current state | Unified implementation | Acceptance test |
|---|---|---|---|
| `enforce_production_boundaries` | Declared mode/environment claims, including model-suggested boundaries. | Host policy and deployment attestation: never let tool/model self-report override installed capabilities or runtime isolation. | A model response cannot claim production-only permissions in a test job. |
| `dispatch_system_telemetry` | Operational telemetry idea. | Read-only metrics/logging adapter under typed event schema, with private data/credentials redacted. | Schema-valid events are correlated to real process/run IDs; no fabricated health. |
| `evaluate_network_readiness` | Reachability/readiness diagnostics idea. | Allowlisted provider health/readiness probes with timeout and egress scope. | Distinguish DNS/TCP/TLS/API/model-ready states; never probe arbitrary private addresses. |
| `ping_live_endpoint` | HTTP endpoint probe helper proposal. | Same provider-probe service, not a second unrestricted URL fetcher. | Redirect and SSRF policies remain in force across all hops. |
| `commit_atomic_state` | Atomic durable state/SQLite helper proposal. | Transactions and revision-safe events/snapshots in the shared persistence layer. | Fault injection cannot leave half-applied state or duplicate successful mutations. |
| `verify_stream_schema` | Schema validation proposal. | Ingress/egress validation in the gateway with explicit versioning and bounds. | Malformed/oversized/unknown events reject safely without coercing into success. |
| `resolve_latency_path` | Latency/path breakdown proposal. | Trace span aggregation for capture, queue, generation, tool, synthesis and playback. | Measured spans and missing intervals are labelled; latency is not guessed by the model. |
| `execute_live_failover_route` | Live provider/network failover proposal. | Operator-configured provider fallback with idempotency and consent; no direct router/kernel modification by model. | Failover never replays an already committed side effect or silently enables remote egress. |
| `calculate_statistical_trends` | Operational trend computation proposal. | One diagnostics aggregation service with declared windows, units and estimators. | Known input series yield correct rates/slopes; absent data stays unavailable. |

**Source:** [A.upgrades](https://github.com/flrtemis/agent/blob/a09f1d25b0aeb5700f03600618aff34408f3fcf6/upgrades.txt#L1-L339)

## Public and embedded history

The seven public snapshots expose 125 commits total (1/1/7/76/21/16/3 by repository). Each default branch is main; no alternate remote branches or tags were found at checkout. Public history is largely recent uploads, so it cannot establish the age of all underlying development. Short public Git histories do not imply the work itself is new or valueless.

[G.bundle](https://github.com/flrtemis/gemma-avatar/blob/c4becc81781fc59d0cf6d7ff52f6099f9943f7b8/gemma-avatar.bundle) contains an additional recoverable history: 12 July 3, 2026 commits, ending at `92bd3bb`. Shared source and every relevant current-versus-bundle difference were compared. Current typed-input/media/text-event additions survive; older shared code does not become a competing runtime.

Deletion review also found the former Gemma `WSL2 CLI output proof.md` (390 lines, primarily README-overlapping captured setup/output), an old Neural Sim README containing only a heading, generated bytecode, and Arena .gitkeep placeholders. No unique executable capability was found in those deletions. Retain the original histories/bundle and proof document as provenance, not duplicate product features.

Before migration, make read-only Git mirrors/bundles and checksummed authored-source/asset inventories. Preserve private state in an encrypted user backup, not a public source archive. Retiring a UI/runtime does not erase prototype history, tests, ideas or authorship. Never flatten the preserved source history and then claim its valuable branches were retained.
