What does “offline” mean here?

After dependencies and chosen engines/assets are installed, the local core can run without Internet access. --offline skips installation and blocks public/DNS model and audio endpoints. A fixed private WSL/LAN IP still requires explicit consent. Generated tools never get network access. Optional external engines must also be configured locally; this is not a host-firewall or absolute privacy guarantee.

Full setup & troubleshooting ↗
When something is unavailable
  • Model not connected: check the configured WSL IP from WSL itself and /api/tags; Windows environment variables do not configure WSL.
  • Generated tool unavailable: check Operations and the actual isolation probe. Namespace restrictions fail closed; there is no unsafe “soft” sandbox.
  • No voice: configure installed local STT/TTS assets or compatible local endpoints. Do not download another large voice model merely to launch the core.
  • Permission denied: unlock with the local operator key; no cloud account sign-in is needed.
  • Resource error: record the exact model/context and RAM/VRAM. Do not raise WSL memory to 24 GB or silently replace the requested model.
